# 免费产品、访客访问与邮箱验证

> 状态：accepted
> 关系：**supersedes ADR 0015**；**partially supersedes ADR 0013、ADR 0014**；关于研究项目、Web 会话归属和访客项目迁移的结论由 [ADR 0017](0017-research-projects-as-web-conversation-boundary.md) 部分取代。实现契约见 [Spec 0003](../specs/0003-free-guest-access-email-verification.md)，术语见 [`CONTEXT-MAP.md`](../../CONTEXT-MAP.md) 与[平台术语表](../contexts/platform/CONTEXT.md)。

## 背景

平台已决定作为面向研究生的免费工具集开放。邀请码把成本控制放在“谁能注册”上，既阻止未登录访问，也不能约束登录后的自动化滥用；它与免费产品的目标不再一致。平台需要同时解决四件事：让未登录访客低门槛试用、用邮箱验证建立可信账号、保留访客历史并允许升级、把滥用和总成本限制放在真正发生开销的边界。

本文中的“访客”“账号”“用户”属于不同限界上下文，不得混用：Web 未登录主体是**访客**，完成邮箱验证后的平台身份是**账号**，论文助手里的**用户**仍只指 QQ 匿名用户。

## 决策

### 1. 产品免费，产品额度与安全控制分离

平台是免费产品，不设置付费墙、会员等级或邀请资格。访客与账号的普通聊天、论文检索和速览均**没有产品次数额度**；账号精读也没有产品次数额度。

唯一的产品次数额度是：每个有效的**访客凭证周期**只有一次**访客精读资格**。精读开始前在 MySQL 中原子预留；系统失败且没有形成可恢复的有效结果时退还，结果成功保存后转为已消费；客户端断线、刷新或放弃查看不退还。清 Cookie、主动清除访客数据或重新取得凭证不能绕过短期 IP 安全限制。

免费与不限产品次数不表示无约束。安全限流独立生效：每个访客或账号同时最多一个模型任务；普通聊天每分钟最多十次；检索或速览每分钟最多三次；账号精读每分钟最多两次；每 IP 每分钟最多三十个 API 请求；登录连续失败五次后逐步延迟，十五分钟后恢复。邮件发送另受邮箱、IP 和全局发送速率限制。QQ 被动回复四次上限仍只是 QQ 通道约束，不是产品额度或 Web 安全限流。

### 2. 访客使用不透明 HttpOnly Cookie

平台为未登录浏览器签发至少 256 bit 随机、不含业务信息的访客凭证，Cookie 名为 `guest_session`，属性为 `HttpOnly`、`SameSite=Lax`、`Path=/`、`Max-Age=2592000`；生产环境必须设置 `Secure`。服务端只保存凭证摘要，不保存明文，也不使用设备指纹。凭证自签发起三十天到期，不因访问滑动续期。

访客凭证不是 JWT、账号或长期身份。完全没有账号 JWT 的 Web 请求按访客处理；携带无效 JWT 的请求必须返回身份错误，不能静默降级成访客。凭证过期、完成访客升级、导入完成或主动清除后立即失效并清除 Cookie。

### 3. MySQL 保存事实，Redis 保存短期协调状态

**MySQL 是持久事实来源**：账号、邮箱唯一性与验证完成时间、密码哈希、`auth_version`、访客凭证摘要与三十天到期时间、访客精读资格状态、会话/消息归属、导入/升级结果、成本明细和审计记录均落 MySQL。需要“只能成功一次”的动作——创建账号、预留/消费精读资格、转移访客会话、清除访客数据——必须靠事务、唯一键或条件更新保证，不能只依赖 Redis 锁。

**Redis 只保存有 TTL 的协调状态**：待验证注册、注册/密码重置验证码摘要、验证码失败次数、重发冷却、登录/API/邮件安全限流、短期并发租约和成本窗口聚合。Redis 不是账号、历史、访客资格或导入状态的事实来源；Redis 数据丢失最多使短期流程重来，不能多发一次访客精读，也不能丢失已保存历史。

安全控制不能因 Redis 故障而失效。Redis 不可用时，验证码发送/校验、访客昂贵操作以及新的检索/速览/精读失败关闭并返回可重试错误；邮箱密码登录、已有账号的资料/历史读取和静态页面在 MySQL 可用时继续服务。全局成本熔断以 MySQL 成本明细可重建，Redis 仅用于快速窗口判断。

### 4. 开放注册使用 QQ SMTP 邮箱验证码

ADR 0015 的邀请码注册门槛被取消。注册提交邮箱、昵称和密码后先形成**待验证注册**，不是账号；密码只保存 argon2id 哈希。平台生成密码学安全随机的六位数字验证码，只保存验证码摘要，通过平台专用个人 QQ 邮箱的 SMTP 服务发送。SMTP 主机、端口、发件地址、授权码和 TLS 模式全部由环境变量注入；授权码不得入库、入文档示例明文或返回 API。

验证码十分钟过期，最多验证五次，同一邮箱六十秒内不可重发；新验证码成功发出后旧验证码立即失效。注册与密码重置使用不同 purpose、Redis key 空间和邮件模板，不能交叉验证。验证码只证明邮箱可接收，不代表邀请、付费或可信自然人。QQ SMTP 默认使用 `smtp.qq.com:465` 的隐式 TLS（也可显式配置 QQ 支持的 STARTTLS 端口）；`SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`、`SMTP_AUTH_CODE`、`SMTP_TLS_MODE` 必须由部署环境提供，禁止使用 QQ 登录密码代替授权码。

只有验证码验证成功后，才在 MySQL 事务中创建邮箱唯一的账号并记录 `email_verified_at`。并发验证同一邮箱最多创建一个账号。邮件发送失败不能创建账号，也不能把一个未成功发送的验证码留成可验证状态。

### 5. 密码重置通过专用验证码撤销旧 JWT

账号可用注册邮箱请求密码重置。请求接口对“邮箱不存在”和“邮件已发送”返回相同外观，防止探测账号。验证码验证成功后原子更新 argon2id 密码哈希并递增 `accounts.auth_version`。

账号 JWT 至少携带稳定用户名、`auth_version` 与过期时间。每次鉴权同时检查签名、过期时间、账号状态和当前 `auth_version`；密码重置、管理员安全处置或其他明确的全端登出动作递增版本，使此前所有 JWT 立即失效，不引入 JWT 黑名单或服务端 session 表。

### 6. 访客历史可升级、可选导入、可主动清除

访客完成邮箱验证注册新账号时，当前凭证下尚未过期的会话在创建账号的同一 MySQL 事务中转给新账号，原凭证失效；这些历史保持为独立会话，成为账号当前会话，不与账号其他会话的消息、候选序号或展示记录拼接。

已有账号在带访客凭证登录时，平台必须先询问是否执行**访客记录导入**：确认后幂等地转移历史并使凭证失效；拒绝时不自动合并，访客记录继续保留到原三十天期限。重复提交导入不得复制消息、重复转移或改变已完成结果。

访客页面必须说明数据最多保存三十天，并提供**访客数据清除**入口。清除会话、消息、展示记录和精读资格状态，吊销当前凭证并清 Cookie；审计和防滥用所需的最小摘要可按安全保留期保留，但不得用于恢复内容。定时清理过期访客及其内容，失败可重试且必须幂等。

### 7. 全局成本熔断与人工急停并存

全部模型与论文处理操作受全局成本熔断保护，默认每小时预算 2 美元、每日预算 10 美元，任一窗口达到阈值就拒绝新的昂贵操作。已成功保存的结果不回滚，注册、登录、验证码校验、历史查看、访客数据清除和管理后台不受熔断影响。预算由运行配置调整，使用统一成本明细计量；无法可靠读出当前窗口成本时，对新的昂贵操作失败关闭。

成本熔断不取代 ADR 0011 的人工全局急停：前者按预算自动触发，后者由管理员主动触发。安全限流、产品额度、熔断、急停必须使用不同错误码和后台状态展示。

### 8. 用服务端开关分阶段上线

上线开关由服务端运行配置控制并记录变更，不信任客户端参数：

- `PLATFORM_OPEN_REGISTRATION_ENABLED`：开放邮箱验证码注册；
- `PLATFORM_GUEST_ACCESS_ENABLED`：允许签发访客凭证和访客聊天；
- `PLATFORM_GUEST_DEEP_READ_ENABLED`：允许访客消费一次精读资格；
- `PLATFORM_GUEST_IMPORT_ENABLED`：允许访客升级/历史导入；
- `PLATFORM_EMAIL_VERIFICATION_REQUIRED`：要求邮箱验证；生产默认且最终必须为 `true`；
- `PLATFORM_COST_BREAKER_ENABLED`：启用成本熔断；生产默认且最终必须为 `true`。

先部署向后兼容的 MySQL/Redis schema 与只读后台观测，再启用邮箱发送和账号验证，再小流量开启访客普通功能、导入和访客精读，最后取消邀请码入口。关闭任一功能开关不得删除数据；关闭访客访问时，账号登录、已有历史与管理后台仍可用。人工急停始终具有最高优先级。

## 对既有 ADR 的修订

### Supersedes ADR 0015

不再要求邀请码，不再消费 `invite_codes`，注册 API 和主导航不再提供邀请码作为准入条件。本次迁移完整删除邀请码接口、服务、DAO、后台页面、`invite_codes` 表及 `accounts.invited_by_code` 字段；执行迁移前必须备份需要留存的历史准入数据。ADR 0015 关于“邀请码控制增长”和“邮箱验证码不采用”的结论全部失效。

### Partially supersedes ADR 0013

保留 HTTP + SSE、逐帧 JSON、复用确定性编排、QQ/Web 适配层分离、会话/消息持久化和任务不承诺跨重启恢复。修订两点：Web 所有者从“只有平台账号”扩展为“访客或账号”；“不继承 QQ 被动回复额度”不等于无限制，Web 仍执行访客精读资格、安全限流、成本熔断和人工急停。

### Partially supersedes ADR 0014

保留独立 `accounts`、邮箱/昵称/稳定用户名三分、可空 QQ 绑定、argon2id、账号 JWT 与管理后台 Basic Auth 分离、密钥只走环境变量。废止“不做邮箱验证码/省掉 SMTP 与 Redis”的结论；邮箱验证成为创建账号的前置。废止“JWT 签发后不能主动失效且只靠短有效期”的结论；改为 JWT 携带并校验 `auth_version`，版本递增即可使旧 JWT 失效。

## 后果

平台增加 Redis 和 QQ SMTP 两项运行依赖，也增加访客数据生命周期、邮件可达性和成本计量的运维责任。回报是注册不再依赖人工发码，访客能无登录试用，账号拥有可验证的恢复锚点，成本控制也从“挡住注册”移动到真正产生开销的边界。所有新增流程的可执行要求、API、数据模型、故障语义和验收标准由 Spec 0003 定义。
