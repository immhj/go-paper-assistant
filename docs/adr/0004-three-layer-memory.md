# 三层记忆：结构化状态、用户原话窗口、受约束的模型旧输出

会话记忆分三层，划分依据是"这份内容是不是一手数据"，因为幻觉累积的来源不是上下文长度，而是把模型自己的输出回灌进它未来的输入。

**第一层，结构化状态。** 每个会话的检索规格、候选列表、序号映射、展示记录与当前聚焦论文——全部是标识符与用户输入。它们按 `conversation_id` 完全隔离。用户说"第 3 篇"时，系统先在当前会话的序号映射中解析为论文 ID，再从数据库取出真实标题、摘要或全文送入模型。

**第二层，用户原话滑动窗口。** 当前会话内最近约 10 条**用户消息**的原话，不含机器人的任何回复。它承载结构化状态无法表达的东西：用户表达过但未被编译进检索规格的偏好（"不想看纯理论的"）、指向上一条回答某个方面的追问、以及意图的延续。用户原话是一手数据，重读不会变质，因此这一层不引入幻觉累积；同时它极便宜，用户消息通常只有几十 token。查询必须带 `conversation_id`，绝不能按用户取跨会话窗口。

**第三层，模型旧输出，默认不进上下文。** 唯一例外：当用户追问模型此前的某个判断时，旧输出可以进入上下文，但**必须与它的一手依据（论文全文或摘要）同时在场**，并标注为待核对。因为原始依据就在旁边，模型能自行发现并纠正偏差，而不是把它当既成事实继承。反过来，**模型旧输出绝不能成为任何事实性判断的唯一来源**——这也是多篇对比必须重读全文、不能复用已生成精读结果的原因。

QQ 客户端本身只有一个物理消息流，但系统提供应用层多会话：`/new <标题>` 新建并切换，`/list` 查看，`/use <编号>` 切换，`/current` 查看当前会话。每个会话的结构化状态、窗口和序号映射分别保存，因此 `/new` 是真正的上下文隔离而不是清空旧数据；旧会话可随时切回。意图路由 Agent 只接收其他 active 会话的编号和标题，不接收其消息或结构化研究状态。

指代解析（"上面这篇"、"那篇 diffusion 的"）是一次独立的模型调用，输入为**当前会话内**已展示论文的序号与标题、最近一条展示记录、用户当前这句话与该会话的原话窗口，输出为序号或"无法确定"。**无法确定时必须反问，不得推测**，且解析结果必须在流式响应的首个分片回显论文标题，让错误在第一秒暴露。序号在单个会话内单调递增；不同会话可以各自拥有 `#3`。

实际的幻觉来源另有三处，与记忆机制无关，需分别处理：论文摘要缺失时应拒绝调用模型而非让它填空；PDF 全文提取结果需先做质量校验再送入分析；精读提示必须约束模型对全文未涉及的内容明确声明无法得知。
