# 账号上传 PDF 建立私有全文，不进入共享全文缓存

> 状态：accepted
> 关系：**amends ADR 0001、partially supersedes ADR 0017 第 1 节与第 6 节中“首版不提供文件上传”的限制**。术语见 [`CONTEXT.md`](../../CONTEXT.md) 中的“全文”“私有全文”“全文上传”。

## 背景

IEEE 订阅论文没有开放 PDF，现有精读流程会直接报错。用户可以凭学校订阅自行下载 PDF，但服务端不应使用用户的机构凭证批量下载。

现有全文缓存挂在全局共享的 `papers` 上，任何账号、访客或 QQ 用户精读同一篇论文时都会复用。若把用户上传的订阅论文全文写入这个缓存，订阅内容就会流向无权访问的其他主体。

## 决策

1. 新增**私有全文**：已验证邮箱的账号在 Web 端上传 PDF，系统提取并校验文本后，按 `(account, paper)` 保存，只供该账号精读。不写入 `papers.fulltext_path`，不保存上传的 PDF。
   “已验证邮箱”沿用平台既有规则：新账号注册时必然已验证；邮箱验证上线前的历史账号（`email_verified_at` 为空）按平台的兼容规则视同有效，也可上传。
2. 访客和 QQ 用户不能上传。他们精读缺全文的论文时，只得到论文链接和“登录 Web 账号后上传”的提示。
3. 上传文件必须确定性地对应所选论文：在提取文本前部查找该论文 DOI，找不到再比对规范化标题；都不一致则拒绝且不保存。不使用模型判断。
4. 复用现有 PDF 校验：50MB 上限、`%PDF-` 文件头、`pdftotext` 提取和全文结构校验。上传按账号做安全限流（每小时 10 次）。
5. 一个账号对一篇论文只保留一份私有全文，重新上传即替换；账号可删除，删除账号时一并删除。已产生的精读结果是历史记录，不随私有全文删除。
6. 上传只建立私有全文，不自动开始精读。精读取全文的优先级为：当前账号私有全文 → 共享全文 → 提示全文上传。

## 后果

订阅内容只在上传者自己的精读中使用，共享缓存的语义保持“开放获取、可复用”。代价是同一订阅论文被不同账号精读时各自上传、各自存一份文本；精读路径要感知调用主体，QQ 通道首版无法使用私有全文。

已排除：上传全文进入全局缓存（订阅内容外泄）、私有全文按研究项目归属（同一账号跨项目需重复上传，且与“项目不复制全文”冲突）、服务端代用户登录机构下载（违反条款、需保管凭证）、上传后自动精读（把上传与模型调用耦合，需在上传请求中绑定会话与精读类型）。
