# 研究项目作为 Web 会话归属与共享研究边界

> 状态：accepted
> 关系：**partially supersedes ADR 0010、ADR 0013、ADR 0016**；保留 ADR 0004 的一手证据约束、ADR 0005 的确定性编排，以及 ADR 0010 的双 Agent、动态最小工具集和单轮单工具结论。术语见 [`CONTEXT.md`](../../CONTEXT.md) 与[平台术语表](../contexts/platform/CONTEXT.md)。

## 背景

论文助手现有 Web 会话直接归属账号或访客，每个会话独立保存研究方向、消息窗口、候选列表和论文序号。这个模型能隔离不同话题，却不能把围绕同一个长期目标的多个会话组织在一起，也没有稳定入口汇集用户真正纳入研究的论文和历次精读结果。

最初考虑过让“工作区”对应用户电脑上的本地文件夹，但纯服务端 Web 产品无法在页面关闭后持续访问本地目录；若改成云端文件工作区，又必须承担 PDF 存储、同步、配额、版权和清理责任。当前需求实际是组织研究活动和复用论文证据，而不是提供通用文件系统。

## 决策

### 1. 使用虚拟研究项目，不建设文件工作区

新增**研究项目**作为 Web 端长期研究边界。项目是 MySQL 中的逻辑结构，不对应本地文件夹，不保存项目专属 PDF、全文副本或任意用户文件。一个项目包含多个会话和项目论文；项目论文下面展示历次精读结果。

项目完全私有，恰好属于一个账号或一个访客凭证。首版不提供分享、协作者、公开链接、文件上传、手写笔记或项目级自由文档。项目数量、会话数量和项目论文数量不设置产品次数额度，但接口仍执行安全限流、并发控制、长度限制和分页。

每个项目在其 owner 范围内拥有稳定的 `project_no`。标题可重复，改名不改变编号；访客项目导入账号时可重新分配编号以避免冲突。项目只能归档和恢复，账号首版不能自行永久删除项目。

### 2. 项目成为 Web 会话的唯一直接归属

归属层级改为：

```text
Account ─┐
         ├─ Project ── Conversation
Guest ───┘

QQ User ───────────── Conversation
```

Web 会话只直接引用 `project_id`，不再同时保存账号或访客 owner，避免项目 owner 与会话 owner 不一致。QQ 会话继续只直接引用 `user_id`，首版不进入项目体系。数据库必须约束一个会话恰好使用 `project_id` 或 `user_id` 其中之一。

账号和访客各自记住当前项目；每个项目分别记住自己的当前会话。切回项目时恢复该项目上次使用的会话。新项目自动创建默认会话。会话创建后固定属于原项目，首版不支持跨项目移动；建错位置时在正确项目新建会话并归档旧会话。

项目、会话和项目论文树只能由用户通过 Web 界面创建、选择、改名、归档、恢复、加入或移出。Agent 不管理这些结构。访客升级或记录导入转移的是整个项目所有权，不属于会话跨项目移动。

### 3. 项目上下文与会话上下文分层隔离

**会话上下文**继续只包含当前会话的研究方向、检索规格、最近用户原话、候选列表、论文序号和展示记录。同一项目内的不同会话也不共享普通聊天、方向、候选列表或序号。

**项目上下文**只包含项目论文及其精读结果。同一项目的会话可以通过受限只读工具按需访问这些资料；不同项目完全隔离。项目内容不自动整体进入模型，其他会话的普通聊天永远不通过项目上下文暴露。

精读结果属于模型旧输出。ADR 0004 的证据规则继续有效：它可以供用户查看、帮助 Agent 定位已有工作，但不得成为新事实性结论的唯一依据。新的比较或研究回答必须重新读取相应论文的摘要或已校验全文，并把旧精读结果标作待核对历史。

### 4. 项目论文引用全局论文，精读结果引用消息

新增 `project_papers` 关系，以 `(project_id, paper_id)` 唯一约束引用现有全局 `papers`。普通检索与速览只产生会话候选，不自动加入项目；用户可从界面主动加入。快速精读或深度精读成功保存时，系统自动创建或恢复项目论文；失败的精读不加入。

“移出项目”是可恢复隐藏，不删除全局论文、全文缓存、历史消息或会话序号。重新加入或再次成功精读时恢复原节点及其历史结果。项目论文不再分配一套 `#N`，避免与会话内稳定序号冲突；界面通过论文卡片选择，自然语言标题不能唯一解析时必须澄清。

新增精读结果关系，关联项目论文、已持久化的机器人消息、来源会话、精读类型（quick/deep）和生成时间，不复制消息正文。保留全部历史并默认展示最新结果。访客清除时，项目、会话、消息、项目论文和结果关系一起清理；全局论文与全文缓存不随之删除。

### 5. Agent 只获得当前项目范围的只读研究能力

Router/Executor 继续遵守 ADR 0010：每轮一个业务目标，Go 根据目标域生成最小工具白名单，参数严格校验。新增能力仅限：分页列出当前项目论文、读取指定项目论文的精读历史，以及基于用户明确指定的当前项目论文回答问题。

当前身份与当前项目由服务端上下文推导，Agent 不能提交任意 `project_id`，也不能借项目工具读取其他项目。不给 Agent 增加项目/会话管理、项目论文加入/移出、文件系统、任意 URL 抓取、SQL 或批量下载能力。

### 6. 下载由浏览器完成，项目不追踪本地状态

“下载论文”只表示服务端按稳定论文身份准备当时有效的开放 PDF 入口，由用户明确点击后交给浏览器保存。系统不自动批量下载，不保存项目专属 PDF，也不记录“已下载”，因为服务端无法确认用户设备是否最终写入成功。论文下载、加入项目和服务端全文缓存是三个独立动作。

### 7. 访客拥有完整项目能力，但仍受既有生命周期约束

账号和访客都能创建并使用项目；唯一的产品次数额度仍是 ADR 0016 定义的访客精读资格。账号项目随账号跨设备可见；访客项目只随当前访客凭证恢复，不承诺跨浏览器或跨设备。

访客注册时，在创建账号的事务中把所有访客项目连同会话、项目论文和精读结果转给新账号。已有账号登录时仍须先明确确认导入。同名项目保持独立，不合并项目、会话、消息或论文序号；拒绝导入则保留到原三十天期限。主动清除或到期清理删除访客拥有的全部项目内容，但不删除共享论文与全文。

### 8. 精读完成使用短事务原子提交

网络抓取、全文抽取和模型调用不得占用数据库事务。它们完成后，在同一个短 MySQL 事务中：

1. 将机器人精读消息标记成功；
2. 创建或恢复当前项目论文；
3. 创建精读结果关系；
4. 正式消费访客精读资格（账号无此步骤）。

任何数据库步骤失败都整体回滚。浏览器断线但服务端已经成功提交时仍算成功；已生成的全局全文缓存可以保留供重试复用。新关系使用外键、唯一键和 owner-scoped 查询保证完整性，不能只依赖单进程锁。

### 9. 用破坏性 Web 数据迁移换取干净归属模型

现有账号和访客的 Web 会话数据不需要保留。实施前必须创建可恢复数据库备份；迁移只删除账号/访客 Web 会话及其消息并清空旧当前会话指针，然后建立项目结构。账号、访客凭证、访客精读资格状态、全部 QQ 用户/会话/消息、全局论文和全文缓存必须保留。

默认项目和默认会话在账号或访客第一次真正使用项目或聊天功能时懒创建，避免仅访问静态页面就制造空数据。不得通过清理旧 Web 会话重置访客精读资格。

## 对既有 ADR 与 Spec 的修订

### Partially supersedes ADR 0010

保留双 Agent 分工、每轮闭合决策、动态最小工具白名单、单轮单工具、严格参数校验和 trace 规则。Web Agent 可在当前会话上下文之外，通过只读工具按需访问当前项目的项目论文与精读历史；项目、会话和项目论文结构管理不再授权给 Web Agent。QQ 的既有会话命令和管理能力不受影响。

### Partially supersedes ADR 0013

保留 HTTP + SSE、逐帧 JSON、复用确定性编排及 QQ/Web 适配层分离。将“Web 会话直接按账号归属”修订为“Web 会话归属项目，项目再归属账号或访客”。

### Partially supersedes ADR 0016

保留免费产品、访客凭证、邮箱验证、访客精读资格、安全限流、成本熔断和导入确认。将“转移访客会话”修订为“转移访客项目及其完整子结构”，并把访客数据清除范围扩展到项目论文和精读结果关系。项目能力不新增产品次数额度。

Spec 0002/0003 中 Web 会话直接使用 `owner_account_id` / `owner_guest_id`、转移独立会话和保留旧 Web 会话的要求，在研究项目实现范围内由本 ADR 取代；其余要求继续有效。实施前应另写研究项目 Spec，定义 API、迁移 SQL、界面状态、错误语义和验收测试。

## 后果

项目为跨会话研究积累提供了稳定边界，同时保持会话消息和研究方向隔离；账号与访客使用同一模型，升级只改变项目 owner。代价是 Web 会话查询必须经过项目归属，精读持久化跨越消息、项目论文、结果关系和访客资格，需要新的事务接口；旧 Web 会话会在迁移中删除。

已排除的方案包括：本地文件夹工作区（服务端无法持续访问）、云端 PDF 文件工作区（引入不必要的存储与版权责任）、每会话一个资料区（无法跨会话积累）、同一会话属于多个项目（上下文归属含糊）、复制 Paper/全文到项目（破坏全局去重）、把全部项目内容自动注入模型（成本与污染不可控），以及向 Agent 开放项目管理或通用文件操作（越过最小权限边界）。
