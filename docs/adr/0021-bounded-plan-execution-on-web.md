# Web 通道有界计划执行：最多 3 步、规划后不再看结果

> 状态：accepted
> 关系：**partially supersedes ADR 0010** 中“每轮工具预算固定为 1”和“意图路由 Agent 与执行 Agent 分离”两条；0010 的会话记忆重建规则、严格参数校验、trace 不进入 Agent 记忆继续有效。术语见 [`CONTEXT.md`](../../CONTEXT.md) 中的“业务目标”“计划”“步骤”“任务”。

## 背景

ADR 0010 规定每轮只调用一个工具，复合需求（“找 5 篇 IEEE 联邦学习论文，对比最相关的两篇”）必须由用户拆成多条消息。开放式 agent 循环能解决这个问题，但会让成本、调用次数和状态一致性失去事先可知的上限，并让模型根据工具结果自行决定后续动作。同时每轮固定的 Router + Executor 两次模型调用，在简单动作上也是纯开销。

## 决策

1. **一条消息仍只有一个业务目标**，但一个业务目标可以由一个计划完成；计划最多 3 步。彼此无关的多个结果不是一个业务目标，按澄清处理。
2. **Router 与执行 Agent 合并为一次规划调用**（QQ 与 Web 都是）：JSON 输出 `respond | clarify | plan`，`plan` 携带有序步骤（工具、参数、可选选择器）。不再输出 `domain`；授权改由 Go 的转移表与既有前置条件（项目工具需要项目范围、Web 短路会话管理）完成。
3. **规划后不再看结果**：步骤之间只能通过小而固定的确定性选择器引用第 1 步检索结果，由 Go 在检索完成后解析，选择范围是检索在本通道实际展示的候选列表。实现只保留两种选择器：`top_relevance(k)`（列表前 k 篇；列表本身按相关性排序，因此“最相关”与“前几篇”是同一个选择）和 `position(n…)`（列表中第 n 篇）；引用会话中已有序号的论文直接写序号，不用选择器。执行中不回传结果给模型，不重新规划。
4. **转移表**：检索最多一次且只能是第 1 步；其后只能是摘要、快速精读、深度精读、对比、研究问答；会话管理与项目工具只能单步；一个计划最多 1 个思考步骤（深度精读、对比、项目论文问答）；同一论文的快速与深度精读不能同在一个计划。
5. **高成本步骤必须源自用户原话**：深度精读与对比由 Go 对用户原话做关键词与否定词匹配确认（与数据源选择同一做法），模型不能自行加入。
6. **计划不合法时追问拆分**，既不截取合法前缀执行，也不把校验错误回传模型重新规划。仅单步计划的参数越界沿用既有处理。
7. **失败即停**：任一步失败或进入需要用户行动的预期状态（零结果、数量不足、需要全文上传、额度不足）时停止，已完成步骤照常保留并说明未执行的步骤。额度按步骤经现有工具闸门检查，不做整计划预检。
8. **每步一条对外消息**，各自拥有展示记录或精读结果，进度显示“步骤 i/n”。
9. **急停与成本熔断只在入口生效**：计划是一个任务，执行中途不在步骤边界中断；成本仍在任务结束时合计记录。单轮成本上限由步数与“最多 1 个思考步骤”保证。
10. **多步计划首版只在 Web 开放**；QQ 的计划恒为 1 步，遇到多步计划追问拆分。待 QQ 纳入成本熔断后再开放；届时 QQ 的回复预算按“1 条计划说明 + 每步 1 条结果，省略各步进度消息”分配，正好占满 4 次被动回复。
11. 现有单步确定性覆盖（数量以原话为准、显式继续检索、斜杠命令直达）原样作用于计划中的检索步骤；多步计划中这些覆盖只读取消息里第一个分隔处（逗号、句号、“然后”等）之前的检索部分，避免“对比最相关的两篇”里的“两篇”被当成检索数量。斜杠命令直接产生单步计划，不经过模型。
12. `agent_trace` 升到 version 3（version 2 是 Router/Executor 双 Agent 的记录）：增加 `plan`（每步工具、参数、选择器、状态、用量、错误码），不再写 `executorUsage`，`routerUsage` 记录规划调用；`tool` 保留为第 1 步工具名以兼容旧读取。后台工具分布按步骤计数，并显示多步计划占比。

## 后果

用户可以在 Web 上用一句话完成“检索 + 精读/对比/问答”，每轮少一次模型调用，调用次数与成本上限仍可事先算出（最多 1 次规划 + 检索内 2 次 + 1 次思考步骤）。代价是：结果不好时系统不会自行换条件重试；计划能力受转移表约束，探索型需求仍然体验一般；两个通道暂时能力不对称；规划 prompt 需要一次携带全部工具说明，每轮多几百 token。

已排除：开放式 ReAct 循环（成本与状态不可控）；步间由模型重新填参数（等于引入“看结果再决定”）；整计划额度预检（需要新的限流接口且存在预检与扣减之间的竞态）；不合法计划截取前缀执行（替用户改写业务目标）；在步骤边界响应急停（改变“急停不中断任务”的语义）。
