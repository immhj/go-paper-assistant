# 精读直接把全文送入模型上下文，不做检索增强

第二次深度精读继续遵循“完整全文直接进上下文、不做 RAG”：DeepSeek 现行模型（`deepseek-flash` / DeepSeek-V4.1-Flash）提供 1M token 上下文，一篇典型论文全文约 3 万 token。第一次快速精读是延迟优化，只选取已校验全文的开头与结论附近重点片段并明确其覆盖边界；它不替代第二次深度精读，也不引入向量库或语义检索。

这与 2023-2024 年"文档问答必须做 RAG"的通行做法相反，所以值得记下来：省掉向量库、切块策略和检索质量调优这一整套组件，不是偷懒，是因为上下文成本的下降让这套组件不再换取任何东西——反而分块会丢失论文里跨章节的关联（方法与实验设置的对应、局限性与 baseline 的呼应），而这些恰好是精读要回答的东西。

若未来需要跨多篇论文做综述式回答（而非单篇分析），这个决策需要重新评估。
