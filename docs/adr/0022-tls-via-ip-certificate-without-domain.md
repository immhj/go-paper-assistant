# 无域名时用 Let's Encrypt IP 证书 + Caddy 终止 TLS

> 状态：accepted

## 背景

服务要部署到国内云（阿里云/腾讯云），对面试官演示并开放给实验室成员使用。国内服务器使用域名必须先 ICP 备案，时间上来不及，因此对外只有一个公网 IP。

明文 HTTP 不可接受：密码、JWT、验证码和后台凭证都会在链路上裸奔；而且 `APP_ENV=production` 下访客 cookie 带 `Secure`，浏览器在 HTTP 下会丢弃它，导致每个请求都新建访客会话。明文与 production 配置无法同时成立。

Let's Encrypt 自 2026-01 起正式签发 IP 地址证书（仅 shortlived 档，约 6 天有效，只支持 HTTP-01 / TLS-ALPN-01 验证）。

## 决策

1. 公网只暴露 Caddy（80/443），由它持有 IP 证书并自动续期；Go 应用只监听 `127.0.0.1:8080`。
2. 应用的 `TRUSTED_PROXY_CIDRS` 只包含 Caddy 所在地址，客户端 IP 从 `X-Forwarded-For` 按现有规则解析。
3. `APP_ENV=production`，访客 cookie 保持 `Secure`。
4. 买机器后先实测外网能否访问 80 端口。若被云厂商拦截（无法完成 HTTP-01 验证），降级为非常用端口上的明文 HTTP，此时后台仍只走 SSH 隧道（ADR 0023），并必须先完成登录与全局限流。降级时需同时把访客 cookie 的 `Secure` 与 `APP_ENV` 解耦，作为显式配置项。

## 后果

无需域名和备案即可获得浏览器信任的 HTTPS。代价：证书 6 天过期，续期完全依赖 Caddy 持续运行且 80/443 可达，续期失败约一周内整站不可用，需要在部署清单里加入证书到期检查；换 IP 即需重新签发；能否签发取决于云厂商对纯 IP 流量的策略，这一点只能上机验证。

已排除：明文 HTTP（凭证裸奔且与 Secure cookie 冲突）；自签名证书（演示首屏即浏览器红色警告）；购买域名（备案周期不满足时间要求，备案完成后可平滑切到域名证书，应用侧无需改动）。
