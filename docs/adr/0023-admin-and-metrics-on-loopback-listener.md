# 管理后台与监控指标只绑定本机回环 listener

> 状态：accepted

## 背景

管理后台（`/admin/`、`/api/admin/*`）与公共 API 挂在同一个 mux、同一个公网端口上，靠 HTTP Basic Auth 保护，且后台登录没有任何限流。后台能查看全部账号、会话和消息，能停用账号和触发全局急停，是整个系统权限最高的入口。即将新增的 Prometheus `/metrics` 同样暴露内部运行细节。

## 决策

1. 进程启动两个 `http.Server`：公共 listener（`APP_ADDR`）只挂公共路由；管理 listener（新配置项，默认 `127.0.0.1:9090`）只挂后台路由和 `/metrics`。
2. 公共 listener 上不再注册任何 `/admin/` 或 `/api/admin/` 路由，访问即 404。
3. 管理 listener 继续保留 Basic Auth 作为第二道防线；`/metrics` 只依赖回环绑定。
4. 运维通过 `ssh -L 9090:127.0.0.1:9090 <server>` 访问后台与指标。容器内通过 compose 端口映射 `127.0.0.1:9090:9090` 暴露到宿主机回环。

## 后果

后台与指标完全不在公网攻击面上，Basic Auth 凭证不再经过公网链路。代价是放弃“随处打开后台”的便利，每次使用都要先建 SSH 隧道；多实例部署时每个实例各有一个管理端口，与 ADR 0006 的单实例前提一致。

已排除：同端口 + 强密码 Basic Auth（凭证随每个请求在公网传输，且仍需额外做后台登录限流）；后台改为账号体系内的 admin 角色走 JWT（工作量大，且仍在公网）；`/metrics` 放公网用 token 保护（多一个需要轮换的密钥和一个攻击面）。
