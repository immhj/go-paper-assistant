# Web 聊天通道以 SSE 复用编排（修订 ADR 0003）

> **Partially superseded：** [ADR 0016](0016-free-guest-access-and-email-verification.md) 将 Web 所有者扩展为访客或账号，并补充访客精读资格、安全限流与成本熔断；[ADR 0017](0017-research-projects-as-web-conversation-boundary.md) 进一步将 Web 会话的直接归属改为研究项目，由项目归属账号或访客。本文的 SSE、复用编排及通道适配结论继续有效。

论文助手要在平台网页里能真正用起来，就需要一条不依赖 QQ 的入口通道。ADR 0003 当初把「单聊 + 流式」定为唯一输出通道，理由是 QQ 群聊被动回复只有 5 分钟、不支持流式、会刷屏。那些约束是 QQ 平台的，不是论文助手领域的；换到浏览器，它们统统不存在。这条 ADR 新增 **Web 聊天通道**，并据此修订 ADR 0003 中「不提供用户 Web 端 / 单聊是唯一能承载长任务的场景」的结论——单聊不再是唯一通道，而是两条并列通道之一。

**传输用 HTTP + SSE，逐帧 JSON**，与 GopherAI-v2 一致：每一帧是一个 JSON 事件（`{"content":"..."}` 文本增量、`{"tool":"..."}` 工具提示、`[DONE]` 结束），避免正文里的空格换行破坏分帧。选 SSE 而不是 WebSocket，是因为对话是单向流式下推、请求—响应边界清晰，SSE 更简单、能直接过 nginx，且仓库里已经有 `gorilla/websocket` 只用于 QQ 网关，不必把它扩散到业务通道。

**关键在于复用而非重写**：Web 通道复用论文助手既有的确定性编排与 Router/Executor（ADR 0005、0010），只替换两样东西——归属键和配额约束。QQ 通道的会话按匿名 QQ 用户归属、受被动回复「一条消息 4 次」的硬约束（ADR 0003）；Web 通道的会话按**平台账号**归属，没有被动回复配额，流可以想开多久开多久。编排层因此必须对「结果往哪送、按什么身份归属」保持通道无关，这也倒逼把 QQ 特有的推送逻辑（`stream_msg_id`、`msg_seq`、`remain_msg_len`、55 分钟兜底）留在 QQ 通道的适配层，不渗进编排核心。

会话数据落在既有的 `conversations` / `messages` 表。归属键的差异用「会话属于账号还是属于 QQ 用户」表达：Web 会话写账号归属，QQ 会话写 QQ 用户归属，一个绑定了 QQ 的账号可以同时看到两者。序号、候选列表、展示记录这些论文助手的核心概念在两条通道里语义完全相同，不因通道而变。

> ADR 0003 里那条待验证结论（「一个流只算 1 次被动回复」）只对 QQ 通道成立，与 Web 通道无关。Web 通道不继承 QQ 的任何配额假设，这一点必须在编排层显式区分，否则会把 QQ 的限制误当成论文助手的固有属性带进网页。

已排除的相邻选项：其一，让 Web 通道走一套独立的、简化的对话实现——被否，那会分叉出两套会话语义，序号与展示记录的规则要维护两遍，正是 ADR 0005 想避免的；其二，用 WebSocket 双向通道——被否，当前对话不需要客户端中途推送，SSE 足够且更省心；其三，第一版任务仍只存进程内存（ADR 0003 的现状）——保留不变，Web 通道同样不承诺跨重启恢复，需要时再统一上持久化任务/发件箱。

**SSE 信封澄清（2026）**：实际协议以 `status` 为事件类型，而非早期示例中的裸 `tool` 字段。除 `message`、`result`、`delta`、`committed`、`completed` 与 `error` 外，Web 通道会发出 `started` 和 `progress`，使浏览器在模型或工具尚未产生答案前也能诚实展示任务进度和本地计时。`completed` 是成功回合的无正文终态，携带最终服务端耗时。阶段文本只描述用户可理解的任务阶段，绝不暴露思维链、原始工具参数、密钥或上游响应正文。`elapsedMs` 是服务端测量的任务耗时；它与总/阶段耗时一起写入版本化 Agent Trace，浏览器用它校正并在历史重载后恢复耗时展示。

模型提供商的 `429` 和 `503` 映射为 `MODEL_BUSY`，调用超时映射为 `MODEL_TIMEOUT`。两者都通过一个安全的 `error` SSE 事件后接 `[DONE]` 结束，不伪装成成功的助手回答，也不在本版本自动重试：自动重试会让等待时间与模型成本不可预测，用户可明确重新发起任务。
