# 版本化账号认证与 Redis 邮箱验证码流程

这批变更把平台注册从邀请码切换为 Redis 邮箱验证码，引入 QQ SMTP、带 `auth_version` 的 JWT，以及回查账号状态和版本的 Platform 鉴权。注册和重置使用 claim/consume 状态机区分 MySQL 工作与一次性验证码消费，登录则不依赖 Redis。目标测试、Compose 配置解析和 gofmt 检查通过，但仍有四个上线阻塞项。Watch for: **confirmed** 未知邮箱的重置请求始终成功，而真实账号会暴露限流或投递错误；**confirmed** 注册与重置各自拥有整套邮件额度；**confirmed** MySQL 成功后 Redis consume 失败会误报业务失败；**confirmed** 生产环境未要求显式提供全部 SMTP 参数。

**Verdict**: NEEDS_CHANGES

## High-level view

Platform 将 argon2id 哈希保存在短期 challenge 中，邮件成功后才激活验证码，再由 DAO 单事务创建账号并可选升级访客。密码重置沿用同一 lease 模型，JWT 通过持久化 `auth_version` 实现撤销。

Redis adapter 以 Lua 原子完成 challenge 状态转换和失败取消，并用 HMAC-SHA256 隐藏验证码。验证码状态按 registration/reset 隔离，但发送计数也被隔离，使邮箱、IP 和全局预算均可跨用途翻倍。

SMTP adapter 支持开发日志、QQ 465 隐式 TLS、STARTTLS 和总 deadline。生产配置会拒绝日志模式，却以默认值补齐未提供的主机、端口和 TLS 模式，未做到配置不全时启动失败。

未知、停用或未验证邮箱直接取得伪重置 token；真实账号额外经过 Redis、SMTP 及错误分支。两条路径的状态与耗时不同，仍可枚举账号。

1. **重置请求可枚举（confirmed）** — 未知邮箱始终返回伪成功，真实账号会返回冷却、Redis 或 SMTP 错误且耗时不同；让伪流程经过等价限流/工作量，并统一外部响应。
2. **邮件预算按 purpose 翻倍（confirmed）** — registration/reset 使用独立邮箱、IP、全局计数；保留 challenge 隔离，但共享发送预算并补跨用途边界测试。
3. **持久化成功被误报失败（confirmed）** — 注册或重置已提交 MySQL 后，Redis consume 失败会返回错误且无法正常重试；以 MySQL 结果为准，将 consume 变成不反转结果的幂等清理或记录可恢复完成状态。

5. **真实 adapter 路径未验证（confirmed）** — 当前未直接执行 Redis Lua 或 SMTP TLS/认证/deadline；上线前运行真实 Redis Compose smoke 和本地 SMTP fake-server 契约测试，不连接真实 QQ SMTP。

## 重置伪流程仍可被状态和耗时枚举

`RequestPasswordReset` 对不存在、停用或未验证账号直接生成随机 token；有效账号则调用 Redis 和 SMTP（`internal/service/platform.go:205-217`）。**confirmed**：真实账号的第二次请求可返回 `ErrResendTooSoon`，Redis/SMTP 故障也会返回错误，未知邮箱却持续成功；正常路径还承担网络延迟。这违反 Spec 0003 R4.3 的相同 202 形状与近似时序要求。伪请求需要执行等价的冷却/IP 协调和近似工作量，并统一外部状态，同时仍只给 active、verified 账号投递邮件。

## purpose 隔离把发送预算扩大一倍

`subjectDigest` 将 purpose 纳入邮箱和 IP 标识，三个 rate key 也包含 purpose（`internal/provider/verification/redis.go:42-46,199-205`）。**confirmed**：同一邮箱可请求 5 封注册邮件再请求 5 封重置邮件，同一 IP 可得到 20+20 封，全局限制也独立应用两次。challenge、cooldown 和验证码摘要应继续隔离，但发送预算应由两个 purpose 共享。

## durable commit 后的 Redis 清理会反转结果

注册在 `CreateAccount` 成功后才 consume，重置也在 `ResetPasswordByEmail` 成功后才 consume（`internal/service/platform.go:155-169,237-247`）。**confirmed**：此时 Redis 故障会让 service 返回 dependency error，但账号/访客升级或密码版本已经提交；challenge 仍可能是 claimed，客户端重试又会失败。MySQL 是事实来源，durable mutation 成功后不应被协调存储清理改写为失败；consume 应是不改变响应的幂等清理，或由可恢复完成记录承接。

## 生产 SMTP 必填字段被默认值掩盖

`config.Load` 给 host、port、TLS mode 填入默认值，生产校验只要求 mode、from 和 auth code（`internal/config/config.go:145-147,263-266`）；`mail.NewSender` 也提供相同默认值。**confirmed**：未部署 `SMTP_HOST`、`SMTP_PORT` 或 `SMTP_TLS_MODE` 仍会启动，违反 ADR 0016、Spec 0003 R3.3 及本批“配置不全 fail validation”的要求。QQ 默认值可保留给 development，但 production 必须区分显式配置与回退值，并测试三个缺失分支。

## adapter 自动化验证边界

单元测试覆盖 JWT 版本、验证码位数/TTL/次数/purpose/冷却、SMTP 失败取消、验证后建号、旧 JWT 撤销和 Redis 无关登录。**confirmed validation gap**：RedisStore Lua 没有直接测试，SMTP 隐式 TLS/STARTTLS/认证/deadline 也没有 fake-server 测试；当前验证的是内存 Fake 和消息格式。按本批约束，真实 Redis 可留最终 Compose smoke，但上线前仍需执行 Lua 并发/TTL smoke，并用本地 SMTP fake server 覆盖协议路径。
