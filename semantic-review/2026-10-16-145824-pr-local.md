# IEEE source via OpenAlex, deterministic venue ranks, and account-private full text

The change adds a second paper catalogue (IEEE, served by OpenAlex inside the paperscraper sidecar with a single Semantic Scholar batch call to fill abstracts), deterministic CCF/JCR/CAS matching against vendored, hash-pinned data, and an account-scoped upload path that turns a user's own PDF into private full text used only by that account's reads. Go picks the source per search, persists ranks with a data version, and resolves full text in the order private → shared → upload prompt. The private-text isolation holds: it never touches `papers.fulltext_path`, the PDF is discarded, and the store is keyed by `(account_id, paper_id)` with cascade delete.

Watch for: the source switch reads the model-generated tool query, not only the user's words (confirmed); an IEEE lookup failure during a read surfaces as a system error instead of the upload prompt (confirmed); the upload/paper match can accept a different short paper that cites the target (likely); Go-side retries multiply OpenAlex quota spend (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

`searchSource` substring-matches "ieee"/"arxiv" over `query + input.Content`. `query` is the router model's `search_papers` argument, so the model can flip the source on its own. That breaks the "only when the user explicitly mentions IEEE" rule.

Quota handling in the sidecar leaks budget and misreports state. A per-second 429 that persists for three attempts is reported as "daily budget exhausted", and every Go-side retry re-runs up to three paid OpenAlex list pages.

Rank matching fails closed on manifest mismatch. But when OpenAlex has no usable source type, a DOI code is accepted against any CCF venue kind, even though ADR 0020 requires the kinds to agree. Unmatched IEEE papers never show "未匹配". They fall through to the citation tiers instead.

Missing full text becomes a prompt when there's no OA URL or the OA download fails. But the `GetByID` refresh that runs before the download turns any lookup failure (404, quota, sidecar down) into "刷新论文信息失败", which is a system error.

The upload match window (first 20,000 runes) is long enough to include the reference list of a 4–6 page paper, and the DOI check is a plain substring test.

<summary>Issues (11)</summary>

1. **Model can choose the data source** (confirmed) — `searchSource` scans the model-written `args.Query` (search.go:47, agents.go:430). Decide from `input.Content` (the user's text) only, and handle negations like "不要 IEEE".
2. **IEEE lookup failure is a system error during reads** (confirmed) — in `fullText` (read.go:113-116), map `GetByID` errors for IEEE (404, quota, outage) to `fullTextUnavailableError` so the user gets the link and upload prompt.
3. **Upload match accepts citing papers** (likely) — the 20k-rune window (private_fulltext.go:21) covers references of short papers, and the DOI test (:106) has no boundary. Shrink the window to roughly the first page, require a non-DOI character after the matched DOI, and add a short-paper test.
4. **Go retries multiply OpenAlex spend** (likely) — 502s and client timeouts make Go re-run full IEEE searches (client.go:111-147, up to 3 × 3 list pages), and the sidecar keeps working after the client gives up. Don't retry IEEE searches on 5xx/timeout, or make the sidecar return a non-retryable code.
5. **Rate-limit 429 reported as daily quota** (confirmed) — three consecutive per-second 429s raise `SourceQuotaExhausted` (ieee.py:140), and users see "今日额度已用完". Only report quota when the header says it's spent; otherwise return a transient error.
6. **CCF kind agreement skipped for unknown types** (confirmed in code, real-world rate possible) — `venue_type=None` (venue_ranks.py:133,143) lets a DOI code match any CCF kind; for example, `10.1109/CC…` could become the Compiler Construction conference. Require a known OpenAlex type for code matches, as ADR 0020 says.
7. **No "未匹配" label** (confirmed) — IEEE papers with no rank match show citation tiers with no rank-status line (search.go:456-467). Show "发表场所等级：未匹配" for IEEE candidates.
8. **Missing abstract is not stated** (confirmed) — text cards print nothing, web cards show the numeric paperId as the title (index.html:269), and abstract-less papers are still sent to the relevance model. Render "暂无摘要" and leave those papers out of `judgeRelevance`.
9. **Post-fill exclusion shrinks results** (confirmed) — after the Semantic Scholar fill, records matching excluded terms are dropped with no refill (ieee.py:230-232), so fewer than `limit` results come back. Over-fetch before the cut, or refill.
10. **Private-fulltext routes on OptionalAuth** (confirmed) — unauthenticated or cross-origin requests mint a guest session before being rejected (router.go:75-77), and the controller comment (papers.go:13) says RequireAccount. Mount the routes with `RequireAccount`, or fix the comment and accept the guest side effect.
11. **Upload prompt points to a missing button** (confirmed) — the read prompt tells any account to use "上传全文 PDF" on the card, but only IEEE cards render it (index.html:278), and the UI never loads the current status. Render the controls whenever upload is possible, and call GET status on render.

### Source decision leaks to the model

```go
// search.go:47
sourceValue := specSourceValue(searchSource(plan.Mode, query+"\n"+input.Content, current.Spec))
// agents.go:430
return a.search(ctx, user, conversation, input, args.Query, ...)
```

`args.Query` comes from the router model's tool call (confirmed). If the model writes "IEEE Transactions on …" into the query for "找 TPAMI 上的论文", the search switches to IEEE. If it writes "arXiv papers on …" for "再来 5 篇" in an IEEE direction, the search silently switches back. The comment at search.go:46 says the source is "never [decided] by the model", but the code contradicts it. The substring test also treats "不要 IEEE 的" as an explicit request for IEEE (confirmed). Tests call `searchSource` directly, so the model-query path isn't covered.

### Full-text resolution: lookup errors bypass the upload prompt

```
private (account scope) ──hit──▶ use, never cached
        │ miss
shared cache (status ok) ──hit──▶ use
        │ miss
GetByID(source, id) ──error──▶ "刷新论文信息失败"   ← system error (read.go:113-116)
        │ ok
OA URL empty ─────────────────▶ upload prompt
Fetch fails (IEEE) ───────────▶ upload prompt
```

For IEEE, `GetByID` goes to OpenAlex `/works/doi:…`. A 404, a 429 that the sidecar maps to `SOURCE_QUOTA_EXHAUSTED`, or a sidecar outage all become a plain error in `readPaper` and `comparePapers`, not the link-plus-upload message. That contradicts ADR 0018 §8 and ADR 0019 §6 (missing full text is a prompt, not a system error) (confirmed). arXiv lookups are synthesized locally and don't hit this path.

### Upload ↔ paper matching window

`uploadMatchesPaper` looks for the DOI (whitespace-stripped substring) or the ≥20-letter compacted title anywhere in the first 20,000 runes. An IEEE letter or a 4–6 page conference paper runs roughly 18–30k characters, so its reference list often falls inside the window. Uploading a different short paper that cites the selected one passes the check, and that text becomes the "private full text" for the wrong paper (likely). The DOI test also has no right boundary, so `10.1109/x.123` matches `10.1109/x.1234` (confirmed; rarer with IEEE's fixed-width modern article numbers). The existing test only covers a citation at around 48k characters. The match fails open toward acceptance. Only the uploader's own reads are affected, which limits the blast radius, but they still get wrong-paper analysis.

### OpenAlex budget and retry amplification

```
Go client (3 attempts on 5xx / transport error / 90s timeout)
  └─ sidecar IEEE.search: up to MAX_PAGES=3 list calls
        └─ _openalex: up to 3 attempts on 429
```

The sidecar maps any non-quota exception (OpenAlex 5xx, `URLError`, timeouts) to 502, and `requestJSON` retries 502s (client.go:126) (confirmed). `ThreadingHTTPServer` keeps serving a request after the Go client times out, so a slow page-3 search can run in parallel with its own retry (likely). With roughly 100 keyless searches per day, a few slow searches can visibly drain the budget.

Separately, `_openalex` raises `SourceQuotaExhausted` on the third consecutive 429 even when `X-RateLimit-Remaining` is absent or positive (ieee.py:140). A burst from concurrent users then shows up as "今日 IEEE 检索额度已用完" (confirmed), which reports a transient condition as a daily one.

### CCF matching when OpenAlex type is unknown

```python
venue_type = venue_type if venue_type in KNOWN_VENUE_TYPES else None   # venue_ranks.py:133
...
and (venue_type is None or venue.venue_type == venue_type)            # :143
```

ADR 0020 §2 requires the CCF kind to agree with OpenAlex before a DOI code is trusted. Here an unknown or nonstandard OpenAlex type ("book series", "other", missing) counts as agreement (confirmed). The IEEE-name guard only filters CCF journals, so a CCF conference with the same code survives. For example, `cc` resolves to `/conf/cc/cc` (Compiler Construction, B) once the two non-IEEE journals are filtered out. How often IEEE sources lack a type in OpenAlex is unverified, so the real-world hit rate is possible rather than confirmed.

### Quality and abstract display for IEEE candidates

`quality()` returns the venue tier only when a rank matched. Otherwise IEEE papers fall into `too_new` / `citation_unknown` / `被引 N 次`, and nothing in Go or the web UI renders "未匹配" (confirmed by search). ADR 0020 §1 and the glossary entry for 发表场所等级 both require showing an unmatched state.

Abstract-less papers are common for IEEE, since OpenAlex gaps go to Semantic Scholar with one no-retry call. For these papers, `renderCandidates` prints neither the abstract nor a "暂无摘要" line. The web card title is `summaryZh || paperId`, so the user sees "#3 1234" (confirmed). The glossary entry for 候选卡片 and ADR 0018 §6 require stating the missing abstract explicitly. `judgeRelevance` still sends those papers (title only) to the model. The results are discarded, so no fabricated summary appears, but the call spends tokens that ADR 0018 §6 says not to spend (confirmed).

In `IEEESource.search`, the final exclusion filter after the abstract fill can drop records already counted toward `limit`, and there is no refill (ieee.py:230-232) (confirmed).

### Private full-text HTTP surface

Same-origin checks, size and signature gates, and the `textContent`/`safeURL` rendering in the new card code are in place, so there's no CSRF or XSS gap. Two remaining gaps:

- The routes are mounted with `optional(...)` (router.go:75-77), while the controller comment (papers.go:13) says RequireAccount. With no Authorization header, `OptionalAuth` creates a guest and sets a cookie before the handler returns 403, and that includes cross-origin PUTs (confirmed). There's no ownership leak, but every probe mints a guest session.
- Upload controls render only for `source==='ieee'` (index.html:278). `fullTextUnavailableMessage` tells every account to click "上传全文 PDF" on the card, so for an arXiv paper with no OA URL the instruction points at a button that doesn't exist. The UI also never calls `GET …/private-fulltext`, so a returning user can't see whether text is already present (confirmed).

### Test coverage

Private-text isolation (other account, guest, QQ) and the IEEE fetch-failure prompt are tested. The 18 Python tests and `go test ./...` pass.

Not tested: the `papers.go` controller (origin mismatch, guest → ACCOUNT_REQUIRED, content type, size), `searchSource` reached through a model query, `GetByID` failure during an IEEE read, an upload whose references fall inside the 20k window, and CCF matching with an unknown venue type.
