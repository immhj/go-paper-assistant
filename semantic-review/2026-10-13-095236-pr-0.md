# Free guest access and email-verified account APIs

The change replaces invite-based entry with email-code registration, password reset, durable account authentication, and 30-day guest sessions for Web chat. Strict bearer handling prevents invalid account credentials from falling back to guests, while admin endpoints remain isolated behind Basic auth. Redis now backs verification, Web guards, and cost windows; startup also adds trusted-proxy IP handling and periodic guest cleanup. Security and product-policy gaps remain in the Web gate and runtime wiring.

Watch for: **confirmed** quick reads consume the guest’s one-time deep-read entitlement and use the account deep-read rate class; **confirmed** the configured per-IP API and login-failure limits are not enforced; **confirmed** cleanup failure logs include raw dependency errors despite the counts-only requirement.

**Verdict**: NEEDS_CHANGES

## High-level view

Requests with any `Authorization` header take the strict account path; requests without one resolve or create an opaque guest session. Account-protected routes re-read durable status and `auth_version`, and only trusted proxy addresses can influence the client IP extracted from `X-Forwarded-For`.

The Web actor abstraction connects accounts and guests to separate conversation ownership and Redis guards. **confirmed:** `read_paper_quick` is classified as deep reading for account rate limits and guest product entitlement, contradicting the free quick-read contract.

The configuration exposes per-IP API and login-failure limits, but runtime assembly passes only cost thresholds to the Web guard. **confirmed:** the IP counter is hard-coded and entered only by chat turns, while login has no failure-delay integration.

Guest cleanup runs at startup and hourly in batches of 100. **confirmed:** its failure path logs the wrapped error object rather than only aggregate counts.

## Quick reads consume the guest deep-read entitlement

**confirmed:** `internal/service/web_gate.go:38-69` maps account `read_paper_quick` to `ToolAccountDeep`, then sends both guest `read_paper_quick` and `read_paper_deep` through `ReserveGuestDeepRead`. A quick read therefore consumes the guest’s only 30-day deep-read entitlement and uses the two-per-minute account deep-read bucket instead of the three-per-minute search/quick bucket. `read_paper_quick` should use `ToolSearchOrQuick` for every actor and bypass guest entitlement reservation; only `read_paper_deep` should reserve and consume that state.

The service tests encode the incorrect behavior in `TestGuestQuickAndDeepShareOneReservation` and `TestAccountQuickAndDeepUseTwoPerMinuteReadLimit`; split those expectations into quick-read and deep-read cases.

## Configured abuse controls stop at parsing

**confirmed:** `internal/config/config.go:83-85` reads `PLATFORM_API_PER_MINUTE`, `PLATFORM_LOGIN_FAILURE_LIMIT`, and `PLATFORM_LOGIN_FAILURE_WINDOW`, but `cmd/server/main.go:76` passes only cost thresholds into `guard.NewRedis`. The guard retains a hard-coded 30-request limit, and `internal/service/web.go:120` invokes it only for Web chat turns. Other API requests do not participate in the required per-IP window, and changing `PLATFORM_API_PER_MINUTE` has no effect. Inject the configured value into a Redis-backed API-boundary guard using the trusted client IP, while preserving the specified Redis-outage availability of account control-plane reads.

**confirmed:** `LoginFailureLimit` and `LoginFailureWindow` have no consumer in the reviewed runtime or service path. Invalid passwords can be retried indefinitely without progressive delay or a 15-minute recovery window. Add a Redis-backed failure tracker, reset it on successful authentication or window expiry, and map enforcement to `429 RATE_LIMITED`.

## Cleanup failure telemetry exceeds the count-only boundary

**confirmed:** `cmd/server/main.go:159-160` logs the wrapped cleanup error under an `error` field, contrary to the explicit counts-only requirement. Record a failure count and accumulated scan/delete/skip totals without serializing the underlying error.
